## Highlights

### The contracts library worked through a second security audit (D5, #114–#119)

On Monday, November 16, a new automated audit ran over all six contracts at
the same commit. Each audit used five attacker profiles. The team re-verified
every claim line by line against the code and specs, and opened one follow-up
tracker per contract on Tuesday. All six trackers were closed by Thursday.
Many claims were refuted as documented behavior. The confirmed ones were fixed
in six PRs merged into the `improve-code-quality` integration branch:

- **DAO: proposals could be backdated
  ([#115](https://github.com/input-output-hk/contracts-library/pull/115)).**
  This was the one major finding fixed in code. A proposal's start time was
  read from the validity range's **lower** bound, which the proposer chooses.
  Backdating it could shrink or skip the draft and cosign window and expire the
  creator's own stake lock at creation. The same stake could then back
  unlimited spam proposals. The start time and the draft lock are now anchored
  to the **upper** bound, which is the fix applied to settings two weeks ago.
- **Vesting: builders refuse bad locks
  ([#114](https://github.com/input-output-hk/contracts-library/pull/114)).**
  A lock whose value didn't match its datum could block partial claims or
  let the beneficiary sweep the excess. Assets not listed in the schedule
  weren't protected, and a malformed schedule could lock funds for good. The
  MeshJS and Tx3 lock builders now reject all three cases. The validator
  doesn't change; the docs now state that value coverage is the builder's job.
- **Upgradeability: two tighter checks
  ([#116](https://github.com/input-output-hk/contracts-library/pull/116)).**
  Forced counters now accept only a `Tick` redeemer, and a counter can no
  longer be created with a stake credential the creator controls. The
  front-running of a V1 upgrade was left unfixed because the counter is a
  non-normative demo.
- **Settings: no lovelace skimming
  ([#117](https://github.com/input-output-hk/contracts-library/pull/117)).**
  A privileged proposer or applier could recreate the settings UTxO at the
  minimum ADA and keep the difference. The continuation may no longer reduce
  lovelace and must keep its other assets exactly.
- **Event-triggered assets: payouts to plain addresses
  ([#118](https://github.com/input-output-hk/contracts-library/pull/118)).**
  An issuer-triggered coupon payout pinned only the payment credential, so a
  hostile issuer could attach its own stake credential, or a datum hash that
  locks the coupon. Payouts must now go to a plain enterprise address. Three
  other findings were refuted after checking the external CIP-113 core, and
  the reasons are recorded in the spec.
- **Smart wallet: a bounded cooldown
  ([#119](https://github.com/input-output-hk/contracts-library/pull/119)).**
  A spend could record a far-future upper bound and block every later spend
  until then. The validity range may now span at most one spending window.

**Some findings were accepted and documented rather than fixed.** Anyone can
spend the single UTxO of a smart wallet with no listed depositors, or of an
event-triggered vault, and so invalidate pending transactions. This was rated
major for the smart wallet. Both are now documented as accepted
denial-of-service limits: no funds can be taken, but transactions can be
delayed. Two smart-wallet griefing limits were also closed as documented
behavior.

Each fix ships regression tests and spec updates. The DAO, settings,
upgradeability, event-triggered and smart-wallet fixes change compiled code,
so their script hashes or blueprints were regenerated.

### CI covers the integration branch (D5, #87)

Sofia Bobbiesi's
**[#87](https://github.com/input-output-hk/contracts-library/pull/87)** merged
on Monday, before the audit fixes. CI now runs on pull requests to any
branch, so the audit PRs were the first into `improve-code-quality` to run
checks. CI finds every end-to-end test file automatically, fails if the
compiled blueprint drifts, and no longer skips devnet tests silently. One
`justfile` drives both local runs and CI, so the two can't drift. The toolchain
is pinned, and the MeshJS suites now run on Yaci DevKit 0.12 with node 11. The
45-minute Tx3 devnet suites moved to a nightly workflow.

The integration branch's PR to `main`,
**[#61](https://github.com/input-output-hk/contracts-library/pull/61)**, was
still open on Sunday.
