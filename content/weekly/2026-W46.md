## Highlights

### `cardano-init` shipped v0.4.0 and v0.4.1 (D3, #126–#143)

**[v0.4.0](https://github.com/input-output-hk/cardano-init/releases/tag/v0.4.0)
shipped on Tuesday, November 10**, with the six new tools covered last week.
It completes DX.05, the setup CLI release candidate, ahead of its November 30
deadline. Its last additions:

- **A `table` command
  ([#126](https://github.com/input-output-hk/cardano-init/pull/126)).** It
  shows every tool by role, with the flag that selects each one, and marks
  experimental and full-stack tools. Lucid Evolution's id is shortened to
  `lucid`.
- **Aiken v1.1.24 with stdlib v4.0.0
  ([#130](https://github.com/input-output-hk/cardano-init/pull/130)).** CI had
  drifted to v1.1.21 and is now pinned to the same version.
- **No more flaky devnet runs
  ([#128](https://github.com/input-output-hk/cardano-init/pull/128)).** About
  1 in 10 devnet jobs failed because Yaci's faucet wasn't ready when the
  devnet reported it was. The test now waits for a successful top-up.
- **Apple Silicon builds
  ([#132](https://github.com/input-output-hk/cardano-init/pull/132)).** The
  first release run was cancelled because GitHub no longer accepts the macOS
  runner that `dist` picks by default.
- **Refreshed docs
  ([#129](https://github.com/input-output-hk/cardano-init/pull/129)).** A new
  demo shows a project being scaffolded and `just test` passing on a local
  devnet. The recording script refuses to write the demo if the test fails.

**[v0.4.1](https://github.com/input-output-hk/cardano-init/releases/tag/v0.4.1)
followed on Thursday**, a patch release that answers a review question:
which tools are actually supported, and which combinations are tested?

- **Every on-chain/off-chain pair is covered
  ([#137](https://github.com/input-output-hk/cardano-init/pull/137)).** Rather
  than test all 40 pairs, every off-chain tool is tested with Aiken, and
  MeshJS runs on a devnet with every on-chain tool. A new check requires each
  on-chain tool's blueprint to have the same shape as Aiken's, so it reads the
  same way to every off-chain tool. The check found two errors in the Scalus
  blueprint. It also found that Scalus compiled to a builtin MeshJS can't
  decode yet, so Scalus is now pinned to the previous protocol version. The
  docs now give each tool a status and list the tested combinations, generated
  from CI.
- **Install commands are tested on Windows too
  ([#138](https://github.com/input-output-hk/cardano-init/pull/138)).** CI had
  skipped 13 of the 52 install commands `doctor` suggests, including every
  `curl`, `winget` and PowerShell one, so Windows had no coverage. They now
  run on clean Ubuntu containers and Windows runners. A command only passes if
  it installs the tool itself. The stricter check found two broken Nix
  commands, for GHC and Rust, which had passed only because the CI machine
  already had those tools.
- **The interactive prompts draw correctly
  ([#136](https://github.com/input-output-hk/cardano-init/pull/136)).** Menus
  no longer erase the text above them, the multi-select shows a cursor, and
  the terminal cursor comes back after Ctrl+C.
- **A manual release checklist
  ([#139](https://github.com/input-output-hk/cardano-init/pull/139)).** CI
  can't see what a person sees in a terminal, so eight manual cases now cover
  the prompts, errors and output. The final version isn't tagged until a
  release candidate passes them. The first run,
  [#142](https://github.com/input-output-hk/cardano-init/issues/142), passed
  all eight before v0.4.1 was tagged.

Paulo Bressan opened
[#144](https://github.com/input-output-hk/cardano-init/issues/144) on how
templates should handle the Dijkstra hard fork. Tools will move to the new
era at different times, so combining, say, an updated Aiken with a MeshJS
still on Conway would break. The proposal records each tool's era and warns
when a project mixes them.

### Dijkstra readiness: five more tools tested on the devnet (D1, #190–#193)

**The tooling was re-tested on node 11.2.0 on November 9
([#190](https://github.com/input-output-hk/devx-updates/pull/190)).** Since
the November 1 run:

- **gouroboros** now decodes every Dijkstra block, and **cardano-js-sdk**
  round-trips all 25 test transactions exactly.
- **db-sync** indexes Dijkstra blocks, then stops at the first PlutusV4
  script.
- **cardano-client-lib** and **Yaci** were tested for the first time. Yaci
  decodes no Dijkstra block, and moves to "Breaks after HF".
- The **IntersectMBO forks of Ogmios and Kupo** decode Dijkstra blocks where
  the released versions stop. They still miss transaction content, so both
  stay "Breaks after HF". The tracker now counts fork commits that haven't
  reached upstream yet, and never treats them as done.

The fix order grows from 19 to 21 steps, and db-sync is still first. Every
critical-path component still has at least one gap. The
[history page](https://input-output-hk.github.io/devx-updates/map/dijkstra/history)
now shows what changed between two assessments.

**Blockfrost
([#191](https://github.com/input-output-hk/devx-updates/pull/191)).** To get
past db-sync's stop, the test patched it to accept PlutusV4. Blockfrost then
serves Dijkstra blocks, but sub-transactions and direct deposits don't show
up, none of the 23 new protocol parameters are served, and `/network/eras`
crashes. db-sync itself stops again when a transaction spends a
sub-transaction's output. The released Blockfrost platform can't connect to
the node at all. Its `main` branch connects, but rejects every
Dijkstra-format transaction on submit.

**cardano-client-lib
([#193](https://github.com/input-output-hk/devx-updates/pull/193)).** The
released versions build ordinary payments and PlutusV3 transactions that the
node accepts. Their stake registration uses the certificates Dijkstra
removes, so it fails. A draft branch builds every new Dijkstra transaction
type the node accepts, including an executed PlutusV4 script: the first
passing devnet results for guards, balance intervals and PlutusV4. It still
loses Dijkstra fields when it signs. The
**[diagnosis](https://github.com/input-output-hk/devx-updates/blob/main/docs/CCL-DIJKSTRA-DIAGNOSTIC.md)**
also notes that cardano-rosetta-java and yaci-devkit build the removed
certificates.

The issues opened from these findings are now tracked on the site
([#192](https://github.com/input-output-hk/devx-updates/pull/192)):
[Blockfrost](https://github.com/blockfrost/blockfrost-backend-ryo/issues/364),
[CSL](https://github.com/Emurgo/cardano-serialization-lib/issues/763),
[cardano-client-lib](https://github.com/bloxbean/cardano-client-lib/issues/752),
[Ogmios](https://github.com/IntersectMBO/ogmios/issues/21) and
[Kupo](https://github.com/IntersectMBO/kupo/issues/13).
